    機能と安全性の改善候補¶

    日本語 | English

    • 基準：v0.0.6。未実装の候補と追加検証、収録済みの対応を整理します。
    • 優先度：P0＝保証を固める、P1＝日常利用・安全性を改善、P2＝効果を測って選ぶ。
    • 未実装の候補は工数・採用版が未確定。個別製品の評価や順位は掲載しません。
    • 方針：ローカルで完結する手軽さ、認証Proxy、既存の隔離・失効・回収を維持します。

    v0.0.6後のUX改善タスク¶

    対象：未リリース（main）。実装と受入条件を次に分けます。

    タスク 提供する操作 受入条件
    1-A ホストAgent PolicyのTUI一覧・検索・継承元・説明 単独で開け、組み込み値とホスト値を区別
    1-B 複製・編集・継承へ戻す・既定値選択 保存前の差分と子ポリシーへの影響、未保存破棄の確認、外部編集競合、0600保存
    2-A 端末転送の回帰試験 改行なしEsc、特殊キー、UTF-8貼付け、ANSI、実行中resize、終了後のstdinと端末復元
    2-B TUIの実操作・画面試験 小さい画面、実PTYでの日本語貼付け、レビュー保存、shell終了後の操作再開
    3 起動段階別の診断案内 元のエラー判定を保持し、選択済み設定を使う次のコマンドを表示
    批判的レビュー 誤保存・競合・誤案内・復帰失敗を検査 実Kata試験と秘密の非表示、自作資源の回収。実AIの推論と物理端末の目視は別に記録

    操作の検討では、K9sの検索・Esc・ヘルプ、VS Codeの設定の適用範囲・検索・リセット、Dockerの診断案内を参照しました。Oaisoでは継承元の表示、保存前レビュー、起動段階ごとの次の確認操作に取り入れています。

    先に保証を固める¶

    優先 項目 現状・追加で必要なこと 完了条件
    P0 Codexの永続状態と対話UI 実装済み（未リリース main）。ワーカー専用DBディスク。通常HOMEと共有workspaceの整合性を維持 停止・再起動・異常終了・容量枯渇・回収を実Kataで確認。既存ワーカーの自動移行や別ワーカーへの履歴移送は対象外
    P0 依存関係の残る検出 依存更新・適用条件の精査は完了（v0.0.4）。検査結果は15→2件。残る2件は使用しないdaemon機能の検出 自動回帰試験は成功。検出は除外せず、非該当の根拠を記録。実Kataの追加確認は通信・失効スイートで実施
    P0 実アカウントの認証受入 独立login・認証専用VM・暗号化保存は実装済み。実アカウントと長期更新は未確認 API・サブスク、更新競合、Proxy再起動、取消、通信中失効、ログ・ファイルへの秘密非残留を確認
    P0 通信・失効の受入を補強 補強完了（v0.0.4）。確認範囲と再実行 DNS・停止失敗は自動試験、通信・既存SSE/WSの失効・隔離停止は実Kataで成功。停止未確認時のCLI通常表示・JSONも検査
    P0 WSL・外側VM・ヘッドレス受入 認証保存の設計と、実際にVMを起動できる条件を区別 install→解錠→login→実行→停止→更新→復旧。KVM等が不足した場合は診断し、弱い隔離へ自動変更しない
    • 実アカウントの認証・推論と実WSLの受入は未実施です。通信・失効は架空の認証情報を使う実Kataで確認しました。
    • 既存の実機確認と未確認条件：テストと動作確認。

    既存機能を強化する¶

    優先 強化項目 追加する内容 守る条件
    P1 実行ごとの利用上限 完了（v0.0.4）。要求数・同時数・本文量・観測tokenの上限 金額の概算と厳密な停止条件を区別。失効しても上流の課金済み処理を取り消せるとは保証しない
    P1 長い処理を誤回収しない 完了（v0.0.4）。--protect-main、CLI／Go APIの活動通知を追加 保護の条件。通知は最大5分で期限切れ、最大寿命は独立。実Kataで更新・解除・idle停止を確認
    P1 診断と監視の集約 完了（v0.0.4）。診断の保存・JSONL出力、CLI／Go APIの起動時間保存 秘密を除外、保持量を制限。外部の常設サービスを必須にしない
    P1 認証brokerの設定支援 完了（v0.0.4）。テンプレート・事前検証・既存TUI。既存秘密の非表示・競合検知 既存brokerを使用。秘密の表示や未知の宛先への注入は追加しない
    P1 更新候補の確認 完了（v0.0.4）。候補の計画・隔離CLI・実Kataの一括検証。結果と成果物hashを保存 差分だけで自動採用しない。失敗時は現行pinを維持し、戻せる状態を残す
    P2 起動・Exec・並列収容の改善 第1段完了（v0.0.4）。実測：Exec 53.1%、2台同時Exec 43.3%短縮。要求内の重複検証を解消 全資産・host/guestの検証を維持。起動は8.2%短縮。収容台数の増加と起動の追加改善は未実装

    追加する機能の候補¶

    優先 機能 最小の提供範囲 完了条件
    P1 機械可読な組み込み仕様 完了（v0.0.4）。パイプ専用API v1・JSON Schema。資源・要求ID・状態・error・capabilityを定義 版違い、取消、応答消失、再送、回収を自動確認。管理socketを公開networkへ出さない
    P1 Python・TypeScriptの薄いSDK 完了（v0.0.4）。同一ホストから作成・実行・照会・回収。両SDKの実Kata受入済み Go APIと同じ再送・権限・失敗の意味を保つ。秘密を引数・標準出力へ出さない
    P2 diskのcheckpoint 完了（v0.0.4）。停止済みrootfsの保存・新規VMへの復元。CLI／Go API RAM保存とは区別。共有mount、書込み中データ、容量、秘密除外、復元互換性を定義
    P2 起動済み環境の事前準備 効果確認用の小さな試作から開始 未割当時は秘密・利用者データを持たせず、割当時に再検証。待機メモリと20%以上の実測効果で判断
    P2 resource制御の追加 完了（v0.0.4）。TCP数・接続元別帯域・プロセス別FD・デバイス別block I/O。CLI／Go API 既存のCPU・メモリ・PID・本文上限と区別。長いstreamを誤って切らず、他実行への影響を抑える
    • 追加agentへの対応条件は今後の対応で管理します。認証分離を緩めて対応数を増やしません。

    セキュリティ強度を上げる¶

    優先 施策 現状の根拠・狙い 検証と残る限界
    P1 VM―Proxy間の暗号化・実行元との結び付け 完了（v0.0.4）。Auth Proxy向けTLS 1.3・実行別証明書。一般egressは対象外 コピーしたtokenだけでは別の実行元から利用できないことを確認。VMが完全に侵害された場合、そのVMに許した操作までは防げない
    P1 配布物の署名・作成元の証跡・依存一覧 実装完了（v0.0.4）。署名付き配布・作成元・SBOM・版の下限。公開物はリリース時に署名・作成元を確認 信頼する鍵で署名を検証してから配置。署名不一致・未知の鍵・意図しない旧版への巻戻しを拒否。署名鍵の侵害対策は別途必要
    P1 保存できる監査記録 完了（v0.0.4）。操作の監査記録。作成・認証変更・許可付き発行・失効・削除の結果を保存 値ではなくID・理由・成否を保存。容量上限・欠損検知・秘密非記録を確認。rootに耐える改ざん防止をローカル保存だけで保証しない
    P1 不正入力・競合・障害の自動試験 完了（v0.0.4）。fuzz・負荷・競合・保存障害の検査。既存のCAS・回収試験も使用 既存試験に不足するfuzz・競合・障害注入を追加。大量・長寿命接続、途中終了、disk fullでも許可側へ倒れないことを確認
    P2 秘密を扱うプロセスの保護 暗号化保存は同一UID・稼働メモリ・swapを保護しない 専用UID、dump制限、解錠期限、鍵の保持時間を検討。Goのメモリ複製やhost rootまで完全に防げるとはしない
    P2 通信規則をさらに細かく限定 実装済み（v0.0.4）。固定origin brokerの完全一致path、CLIのmethod指定、TUI・Go API・設定ファイル 従来の配下指定を維持。拒否時は秘密を読み出さない。一般CONNECTのTLS内検査、query・body制限は対象外
    • 上流の実APIキー・OAuth access/refresh/ID tokenは引き続き認証Proxyだけで保持します。
    • 作業VMへ渡すのは、上流認証に使えない短命・実行限定のProxy用認証情報です。証明書のhost側発行鍵は渡しません。
    • 暗号化は権限管理や回収の代わりにはなりません。保護対象と未確認条件をセキュリティに明記します。

    設計への影響が大きいものは別に判断する¶

    案 変わる契約 先に確認すること
    通信規則の動的変更 v0.0.4で明示的なProxy単位の即時変更を追加。手順と制限 規則の世代、適用完了応答、既存接続の終了、途中失敗と再起動時の復元
    汎用TLS復号・L7制限 guestの信頼CAと対応protocol pinning、HTTP/2・gRPC・WS、署名要求、秘密のecho、ログ、追加負荷
    メモリsnapshot・VM fork process・RAM・接続・ID・期限を保存／複製 token再発行、秘密残留、CPU互換、外部の処理を二重実行しないこと
    別OS・複数ホスト・複数利用者 信頼済み単一ホストoperatorという前提 利用者認証、権限、容量、配置、相互認証、監査、障害回収
    認証プロセスの専用UID化 profile・キーリング・管理サービス間の権限 既存profileの移行、headless／WSLでの解錠、解除・回収、rootの信頼範囲

    進める順序¶

    1. P0の検証と依存対応を優先し、既存の保証を固める。
    2. 利用上限、監査、配布署名、組み込み仕様のうち必要性の高いものを小さく追加する。
    3. 速度改善は測定から開始し、事前起動・状態保存は小さな試作で費用と効果を確認する。

    4. 認証・隔離・失効・回収を弱める変更は採用しない。

    5. 実装済み：既定拒否、実行別モデル制限、PID profile、credential broker、Create→Start、PTY・files・jobs、独立login・暗号化保存。新規機能として重ねて追加しません。

    6. 既存の追加制御・Go APIはv0.0.2、独立login・キーリング＋暗号化・状態／配布版更新の一括案内はv0.0.3が初収録です。詳しい条件は各機能の既存ページを参照してください。
