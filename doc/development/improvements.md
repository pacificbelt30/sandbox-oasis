# 機能と安全性の改善候補

**日本語** | [English](../en/development/improvements.md)

- 対象：公開版v0.0.3。以下は**未実装の候補、または既存機能への追加検証**です。
- 優先度：P0＝保証を固める、P1＝日常利用・安全性を改善、P2＝効果を測って選ぶ。
- 実装・工数・採用版は未確定。個別製品の評価や順位は掲載しません。
- 方針：ローカルで完結する手軽さ、認証Proxy、既存の隔離・失効・回収を維持します。

## 先に保証を固める

| 優先 | 項目 | 現状・追加で必要なこと | 完了条件 |
|---|---|---|---|
| P0 | 依存関係の残る検出 | [既存検査](dependency-security.md)に15件のsymbol検出。攻撃成立の件数とは別 | 実際に使う経路、修正版、互換性、緩和策を精査し、必要な回帰試験を通す |
| P0 | 実アカウントの認証受入 | 独立login・認証専用VM・暗号化保存は実装済み。実アカウントと長期更新は未確認 | API・サブスク、更新競合、Proxy再起動、取消、通信中失効、ログ・ファイルへの秘密非残留を確認 |
| P0 | 通信・失効の受入を補強 | [既存の通信試験](../testing.md)を再利用し、不足する条件だけ追加 | DNS、IPv4/IPv6、private/metadata、redirect、CONNECT、SSE/WS、停止失敗を確認。停止未確認を遮断完了と表示しない |
| P0 | WSL・外側VM・ヘッドレス受入 | 認証保存の設計と、実際にVMを起動できる条件を区別 | install→解錠→login→実行→停止→更新→復旧。KVM等が不足した場合は診断し、弱い隔離へ自動変更しない |

- 認証受入は、使用するアカウント・利用条件・料金を決めてから実施します。この文書の作成で実認証・推論は行いません。
- 既存の実機確認と未確認条件：[テストと動作確認](../testing.md)。

## 既存機能を強化する

| 優先 | 強化項目 | 追加する内容 | 守る条件 |
|---|---|---|---|
| P1 | 実行ごとの利用上限 | 許可モデルに加え、要求数・同時接続数・利用量の上限 | 金額の概算と厳密な停止条件を区別。失効しても上流の課金済み処理を取り消せるとは保証しない |
| P1 | 長い処理を誤回収しない | メイン処理にも実行中の印や定期通知を持たせる | 現在のidleは管理API活動が基準。通知停止時の扱いを決め、最大寿命と混同しない |
| P1 | 診断と監視の集約 | 既存status・拒否イベント・起動時間・メモリ値を保存・出力 | 秘密を除外、保持量を制限。外部の常設サービスを必須にしない |
| P1 | 認証brokerの設定支援 | 固定宛先・許可path・methodのテンプレート、事前検証、TUI | 既存brokerを使用。秘密の表示や未知の宛先への注入は追加しない |
| P1 | 更新候補の確認 | 既存の静的変更検知から、固定CLI・実機の互換確認へ接続 | 差分だけで自動採用しない。失敗時は現行pinを維持し、戻せる状態を残す |
| P2 | 起動・Exec・並列収容の改善 | 工程別の時間、待ち、CPU、メモリ、I/Oを測り、支配的な処理を最適化 | 同じ条件で前後比較。20%以上を狙える根拠を持ち、隔離検証を省略しない |

## 追加する機能の候補

| 優先 | 機能 | 最小の提供範囲 | 完了条件 |
|---|---|---|---|
| P1 | 機械可読な組み込み仕様 | 公開Go APIの資源・要求ID・状態・error・capabilityを定義 | 版違い、取消、応答消失、再送、回収を自動確認。管理socketを公開networkへ出さない |
| P1 | Python・TypeScriptの薄いSDK | 同一ホストから作成・実行・照会・回収 | Go APIと同じ再送・権限・失敗の意味を保つ。秘密を引数・標準出力へ出さない |
| P2 | diskのcheckpoint | 作業環境のdisk状態を保存し、新しい環境へ復元 | RAM保存とは区別。共有mount、書込み中データ、容量、秘密除外、復元互換性を定義 |
| P2 | 起動済み環境の事前準備 | 効果確認用の小さな試作から開始 | 未割当時は秘密・利用者データを持たせず、割当時に再検証。待機メモリと20%以上の実測効果で判断 |
| P2 | resource制御の追加 | 接続数・転送量・file descriptor・I/O等の上限を検討 | 既存のCPU・メモリ・PID・本文上限と区別。長いstreamを誤って切らず、他実行への影響を抑える |

- 追加agentへの対応条件は[今後の対応](../future-work.md)で管理します。認証分離を緩めて対応数を増やしません。

## セキュリティ強度を上げる

| 優先 | 施策 | 現状の根拠・狙い | 検証と残る限界 |
|---|---|---|---|
| P1 | VM―Proxy間の暗号化・実行元との結び付け | [現状](../security.md#通信と認可)は専用network上のHTTPとBearer token。短命の実行用認証で接続元を確認する案 | コピーしたtokenだけでは別の実行元から利用できないことを確認。VMが完全に侵害された場合、そのVMに許した操作までは防げない |
| P1 | 配布物の署名・作成元の証跡・依存一覧 | [現在のmanifest](../security.md)はchecksumで、独立した配布元署名ではない | 信頼する鍵で署名を検証してから配置。署名不一致・未知の鍵・意図しない旧版への巻戻しを拒否。署名鍵の侵害対策は別途必要 |
| P1 | 保存できる監査記録 | 既存の拒否イベントに加え、作成・認証変更・許可変更・失効・削除の結果を記録 | 値ではなくID・理由・成否を保存。容量上限・欠損検知・秘密非記録を確認。rootに耐える改ざん防止をローカル保存だけで保証しない |
| P1 | 不正入力・競合・障害の自動試験 | 認可、URL/path、JSON、Store更新、停止・回収が重要な境界 | 既存試験に不足するfuzz・競合・障害注入を追加。大量・長寿命接続、途中終了、disk fullでも許可側へ倒れないことを確認 |
| P2 | 秘密を扱うプロセスの保護 | [暗号化保存](local-credential-store.md)は同一UID・稼働メモリ・swapを保護しない | 専用UID、dump制限、解錠期限、鍵の保持時間を検討。Goのメモリ複製やhost rootまで完全に防げるとはしない |
| P2 | 通信規則をさらに細かく限定 | [一般CONNECT](../proxy-policy.md)はTLS内のSNI・URLを検査しない | 固定origin brokerでpath・methodを絞れる範囲を先に使う。SNI照合だけではHTTP Host・path制限にならない |

- 上流の実APIキー・OAuth access/refresh/ID tokenは引き続き認証Proxyだけで保持します。
- 作業VMへ渡す候補は、上流認証に使えない短命・実行限定のProxy用認証情報です。証明書を使う場合も、host側の発行鍵は渡しません。
- 暗号化は権限管理や回収の代わりにはなりません。保護対象と未確認条件を[セキュリティ](../security.md)に明記します。

## 設計への影響が大きいものは別に判断する

| 案 | 変わる契約 | 先に確認すること |
|---|---|---|
| 通信規則の動的変更 | 現在は固定規則＋VM全体の隔離停止 | 規則の世代、適用完了応答、既存接続の終了、途中失敗と再起動時の復元 |
| 汎用TLS復号・L7制限 | guestの信頼CAと対応protocol | pinning、HTTP/2・gRPC・WS、署名要求、秘密のecho、ログ、追加負荷 |
| VM―Proxyの相互認証 | tokenだけの接続から、実行元認証を追加 | 発行・更新・失効、Proxy再起動、時間ずれ、移行期間、接続再利用と遅延 |
| メモリsnapshot・VM fork | process・RAM・接続・ID・期限を保存／複製 | token再発行、秘密残留、CPU互換、外部の処理を二重実行しないこと |
| 別OS・複数ホスト・複数利用者 | 信頼済み単一ホストoperatorという前提 | 利用者認証、権限、容量、配置、相互認証、監査、障害回収 |
| 認証プロセスの専用UID化 | profile・キーリング・管理サービス間の権限 | 既存profileの移行、headless／WSLでの解錠、解除・回収、rootの信頼範囲 |

## 進める順序

1. P0の検証と依存対応を優先し、既存の保証を固める。
2. 利用上限、監査、配布署名、組み込み仕様のうち必要性の高いものを小さく追加する。
3. 速度改善は測定から開始し、事前起動・状態保存は小さな試作で費用と効果を確認する。
4. 認証・隔離・失効・回収を弱める変更は採用しない。

- 実装済み：既定拒否、実行別モデル制限、PID profile、credential broker、Create→Start、PTY・files・jobs、独立login・暗号化保存。新規機能として重ねて追加しません。
- 既存の追加制御・Go APIはv0.0.2、独立login・キーリング＋暗号化・状態／配布版更新の一括案内はv0.0.3が初収録です。詳しい条件は各機能の既存ページを参照してください。
