# 機能と安全性の改善候補

**日本語** | [English](../en/development/improvements.md)

- 基準：v0.0.6。未実装の候補と追加検証、収録済みの対応を整理します。
- 優先度：P0＝保証を固める、P1＝日常利用・安全性を改善、P2＝効果を測って選ぶ。
- 未実装の候補は工数・採用版が未確定。個別製品の評価や順位は掲載しません。
- 方針：ローカルで完結する手軽さ、認証Proxy、既存の隔離・失効・回収を維持します。

## セキュリティ強度を上げる

| 優先 | 施策 | 現状の根拠・狙い | 検証と残る限界 |
|---|---|---|---|
| P1 | VM―Proxy間の暗号化・実行元との結び付け | **完了（v0.0.4）**。[Auth Proxy向けTLS 1.3・実行別証明書](../guides/worker-tls.md)。一般egressは対象外 | コピーしたtokenだけでは別の実行元から利用できないことを確認。VMが完全に侵害された場合、そのVMに許した操作までは防げない |
| P1 | 配布物の署名・作成元の証跡・依存一覧 | **実装完了（v0.0.4）**。[署名付き配布・作成元・SBOM・版の下限](../guides/signed-releases.md)。公開物はリリース時に署名・作成元を確認 | 信頼する鍵で署名を検証してから配置。署名不一致・未知の鍵・意図しない旧版への巻戻しを拒否。署名鍵の侵害対策は別途必要 |
| P1 | 保存できる監査記録 | **完了（v0.0.4）**。[操作の監査記録](../guides/audit.md)。作成・認証変更・許可付き発行・失効・削除の結果を保存 | 値ではなくID・理由・成否を保存。容量上限・欠損検知・秘密非記録を確認。rootに耐える改ざん防止をローカル保存だけで保証しない |
| P1 | 不正入力・競合・障害の自動試験 | **完了（v0.0.4）**。[fuzz・負荷・競合・保存障害の検査](security-tests.md)。既存のCAS・回収試験も使用 | 既存試験に不足するfuzz・競合・障害注入を追加。大量・長寿命接続、途中終了、disk fullでも許可側へ倒れないことを確認 |
| P2 | 秘密を扱うプロセスの保護 | [暗号化保存](local-credential-store.md)は同一UID・稼働メモリ・swapを保護しない | 専用UID、dump制限、解錠期限、鍵の保持時間を検討。Goのメモリ複製やhost rootまで完全に防げるとはしない |
| P2 | 通信規則をさらに細かく限定 | **実装済み（v0.0.4）**。[固定origin broker](../guides/credential-broker.md)の完全一致path、CLIのmethod指定、TUI・Go API・設定ファイル | 従来の配下指定を維持。拒否時は秘密を読み出さない。一般CONNECTのTLS内検査、query・body制限は対象外 |

- 上流の実APIキー・OAuth access/refresh/ID tokenは引き続き認証Proxyだけで保持します。
- 作業VMへ渡すのは、上流認証に使えない短命・実行限定のProxy用認証情報です。証明書のhost側発行鍵は渡しません。
- 暗号化は権限管理や回収の代わりにはなりません。保護対象と未確認条件を[セキュリティ](../security.md)に明記します。

## 設計への影響が大きいものは別に判断する

| 案 | 変わる契約 | 先に確認すること |
|---|---|---|
| 通信規則の動的変更 | v0.0.4で明示的なProxy単位の即時変更を追加。[手順と制限](../guides/live-policy.md) | 規則の世代、適用完了応答、既存接続の終了、途中失敗と再起動時の復元 |
| 汎用TLS復号・L7制限 | guestの信頼CAと対応protocol | pinning、HTTP/2・gRPC・WS、署名要求、秘密のecho、ログ、追加負荷 |
| メモリsnapshot・VM fork | process・RAM・接続・ID・期限を保存／複製 | token再発行、秘密残留、CPU互換、外部の処理を二重実行しないこと |
| 別OS・複数ホスト・複数利用者 | 信頼済み単一ホストoperatorという前提 | 利用者認証、権限、容量、配置、相互認証、監査、障害回収 |
| 認証プロセスの専用UID化 | profile・キーリング・管理サービス間の権限 | 既存profileの移行、headless／WSLでの解錠、解除・回収、rootの信頼範囲 |

## 進める順序

1. P0の検証と依存対応を優先し、既存の保証を固める。
2. 利用上限、監査、配布署名、組み込み仕様のうち必要性の高いものを小さく追加する。
3. 速度改善は測定から開始し、事前起動・状態保存は小さな試作で費用と効果を確認する。
4. 認証・隔離・失効・回収を弱める変更は採用しない。

- 実装済み：既定拒否、実行別モデル制限、PID profile、credential broker、Create→Start、PTY・files・jobs、独立login・暗号化保存。新規機能として重ねて追加しません。
- 既存の追加制御・Go APIはv0.0.2、独立login・キーリング＋暗号化・状態／配布版更新の一括案内はv0.0.3が初収録です。詳しい条件は各機能の既存ページを参照してください。
