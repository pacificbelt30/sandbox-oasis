# TUIでサンドボックスを使う

**日本語** | [English](../en/guides/sandbox-ui.md)

利用可能：**未リリース（main）**。AI認証を使わず、Kata VMの作成、workspace内のファイル確認・転送、Webアプリの確認ができます。

## 前提と起動

- このページの新規作成・ファイル操作・プレビュー管理は**未リリース（main）**です。公開版のインストールだけでは追加されません。[ソース版の配置手順](../setup.md#ソースからビルドする場合)に沿い、CLI・node・guard・loggerを同じバンドルから配置してください。
- Linux/KVMのノードを管理者が準備し、利用者がノードソケットへ接続できること。通常操作は管理グループ所属の通常ユーザーで行います。
- 書き込み可能rootfsには、ノードで設定した[quota対応の専用ストレージ](storage-migration.md)が必要です。既存データのある環境は先に移行手順を確認してください。
- 作業するホストのプロジェクトディレクトリから、次を実行します。

```bash
oaiso --version
oaiso runtime-check
```

`runtime-check`が終了コード0で完了したら先へ進みます。失敗時は表示された復旧案内を確認します。Kata検証は省略しません。

## ワーカーイメージを用意する

互換イメージがまだなければ、同じ通常ユーザーで組み込み`plain`テンプレートをビルドします。プロジェクトのDockerfileを使う場合は[イメージ作成ガイド](../commands/build.md)へ進んでください。

```bash
oaiso build --template plain --tag codex-dock:latest
```

- イメージがすでに準備・検査済みなら、このビルドは不要です。
- ビルドにはホストからレジストリやパッケージ配布先への通信が必要です。VMの`Offline`設定とは別です。
- `plain`はCodex／Claude Codeなどのツールも含みます。`--no-ai`はホストのAI資格情報と認証Proxyを使わない指定で、ツールのアンインストールではありません。
- `login`、認証プロファイルの登録、`init`、認証Proxyの起動は、この認証なしの手順では不要です。

## TUIを開く

イメージの準備後、共有するプロジェクトのディレクトリから起動します。

```bash
oaiso ui
```

| 操作 | 入力 |
|---|---|
| メニューから選ぶ | `Actions F2`をクリック、または`F2`／`Space` |
| メニューの選択・決定・取消 | `↑↓`で選択、`Enter`か表示キーで決定、`Esc`で戻る |
| VM作成・接続 | `N`で作成、対象を選んで`C`でシェルへ接続 |
| ファイル・Web・詳細 | `F`でファイル、`U`でプレビュー、`I`で詳細 |
| 管理workspace・復元 | `M`で一覧・再利用・削除、停止VMの`K`で保存、`Z`で新規VMへ復元（[詳細](managed-workspaces.md)） |
| 差分・成果物・期限 | `W`で差分と選択回収、`L`で期限・容量・監視 |
| 単発コマンド | `X`で入力し、`Run`で実行。実行前は入力欄・ボタンのどこでも`Esc`で取消 |
| フォームを移動 | `Tab`／`Shift-Tab`。チェック項目は`Space`で切り替え |

状態に応じて使える操作をメニューに表示します。狭い画面で省略された情報も、`I`で確認できます。

一覧の詳細欄は、同じVMの自動更新ではスクロール位置を保持し、別のVMを選ぶと先頭へ戻ります。名前・タスクなどの`[red]`のような文字列もそのまま表示します。コマンド入力とAgent policyの編集ダイアログは、画面幅に合わせて縮小します。

## VMを作成する

1. 一覧画面の`Actions F2`から`New sandbox`を選ぶか、`N`を押します。
2. ホストのプロジェクト、用意したイメージ（上の例では`codex-dock:latest`）、必要なら起動コマンドを指定します。空欄ならVMを待機状態に保ち、作成後に`C`でシェルへ接続します。
3. CPU・メモリ、共有フォルダ、通信設定を確認し、`Review`を選びます。
4. 確認画面で作成を承認します。`Created sandbox`が出たら一覧へ戻り、対象を選んで`C`で接続、`Enter`でログを確認します。

| 項目 | 既定値・意味 |
|---|---|
| Runtime | Kata。通常の起動検証を通ります |
| Name | 空欄なら自動生成 |
| Image | 空欄ならホスト・プロジェクト設定の解決規則を使用 |
| Command | 空欄なら`exec sleep infinity`で待機。指定内容はホストのプロセス引数に含めずstdinで渡す |
| CPU / memory | ノードが承認したプロファイルから選択。既定なら既存設定を継承 |
| Project access / Image rootfs | 既存設定の継承、読み取り専用、書き込み可能から選択 |
| Storage | ノードのrootfs byte・inode上限を表示。共有ホストフォルダの容量は対象外 |
| Internet access | 既定はOffline。Host policy、依存レジストリ、指定ドメインも選択可。ホストの禁止規則は維持 |
| Enable AI services (optional) | 既定は無効。無効時は認証Proxy・資格情報を使わない。一般通信の許可には資格情報を持たないProxyを使う |
| Extra mounts | 1行に1つ、通常の`--mount`形式。共有範囲を確認して指定 |

- 起動は通常の`oaiso run`を使用します。未指定項目にはホスト・プロジェクトの既定値が適用されます。ホスト設定は変更しません。
- `Esc`は確認・入力を取り消します。起動中は完了を待ちます。失敗表示に名前が出た場合は、再試行前に一覧で残存を確認してください。
- プロジェクトが書き込み可能なら、ゲストの変更は共有ホストフォルダへ反映されます。隔離が必要な作業ではコピーしたプロジェクトや読み取り専用共有を使ってください。
- `Enable AI services (optional)`を有効にする場合は、[認証設定](authentication.md)を先に行ってください。

## 元のプロジェクトを変更せず試す

利用可能：**未リリース（main）**。作成フォームの`Workspace source`で`Independent Git copy`を選び、`New copy directory`に新しい絶対パスを指定します。

1. 通常ユーザーで、共有対象の外にコピー保存用の専用フォルダーを準備します。次は新規作成の例です。既存の所有者限定フォルダーを使う場合は作成不要です。

    ```bash
    mkdir -m 700 "$HOME/oaiso-copies"
    ```

2. コピー先に、例えば`/home/alice/oaiso-copies/experiment-1`を指定します。`alice`は自分のユーザー名へ置換します。親は自分が所有する0700のフォルダー、コピー先は未作成であることが必要です。
3. `Review`または`Ctrl-R`で元プロジェクト・コピー先・固定するコミットを確認します。スクロールして内容を読み、`Tab`で`Cancel`／`Confirm`へ移動します。
4. 承認すると独立コピーを作成し、そのコピーを`/workspace`へ共有して起動します。元プロジェクトは自動で共有しません。追加mountは別途ホストのデータを公開します。

| 対象 | コピーの扱い |
|---|---|
| コミット済みファイル | レビューで表示したコミットを固定。Gitに保存した秘密も含む |
| 未コミット・未追跡・ignoredファイル | コピーしない |
| Gitメタデータ | 独立したオブジェクトを作成。外部`.git`ポインタ、linked worktree、共有オブジェクト、Gitメタデータのsymlinkは拒否。メタデータは最大100,000項目・64階層 |
| 起動失敗・VM削除・保持期限切れ | コピーはホストへ残す。既存コピーを再試行時に上書き・自動採用しない |
| 通常の共有方式 | 従来どおり利用可能。`Project access`で読み取り専用も選べる |

コピー先エラーは親フォルダーの所有者・0700・symlink・既存パスを確認します。コピー元は実体の`.git`ディレクトリを持つリポジトリのルートを指定してください。キャンセルではコピーを作成しません。

現在の未コミット・未追跡ファイルやGit管理外のフォルダーを試す場合は、[容量付き管理workspace](managed-workspaces.md)を選べます。専用ディスクで元ファイルを共有せず、停止VMの保存・新規VMへの復元も行えます。

## よく使う環境を保存する

利用可能：**未リリース（main）**。VM作成フォームで設定し、`Save environment`／`Ctrl-S`から名前を付け、保存内容をレビューして承認します。読み込みは`Load environment`／`Ctrl-O`から選び、内容をレビューします。読み込み後にも通常の起動レビューが必要です。

| 保存する | 保存しない・読み込み時の扱い |
|---|---|
| イメージ・起動コマンド・資源プロファイル | ワーカー名・プロジェクト・コピー先のパスは保存しない |
| workspace方式・管理容量／inode上限・読み取り専用設定 | 入力した追加mountは保存せず、読み込み時もクリア |
| 通信モード・明示ドメイン・期限設定 | AI資格情報・認証設定・AI有効化は保存せず、読み込み後はAI無効 |

- ホスト・プロジェクトの既定値は引き続き適用します。読み込みは、ホスト設定にある追加mountなどを無効にする指定ではありません。
- 起動コマンド自体には秘密を書かないでください。保存レビューにはコマンド全体を表示します。
- 名前は`Python検証`など、日本語を含む1〜64文字の文字・数字と、`.`・`_`・`-`を使えます。先頭は文字か数字です。
- 保存先はホストの`~/.config/codex-dock/sandbox-environments/config.json`（`XDG_CONFIG_HOME`を設定した場合はその配下）。親0700・ファイル0600で、最大32環境です。
- 保存済み一覧の`D`は設定だけを確認後に削除し、既存VMには影響しません。同名保存は置換する内容を表示します。同時編集を検出した場合は下書きを保ち、保存画面を開き直して再確認します。
- 読み込み時に資源プロファイルが存在しない場合は利用を拒否します。ホスト側の通信許可上限は緩和しません。

## 寿命と容量を確認・管理する

利用可能：**未リリース（main）**。新規VMでは次を任意で設定できます。3つとも空欄ならホスト・プロジェクトの既定値を維持します。上書きする場合は3つとも指定し、無効にする制限は`0s`にします。

| 作成項目 | 動作・例 |
|---|---|
| `Maximum lifetime` | 作成時刻からの最大寿命。例：`2h`。再起動しても起点は戻らない |
| `Idle timeout` | 管理側のexec・活動通知がない期間。例：`30m`。ゲストCPU・ファイル更新・通信のidleではない |
| `Retention after exit` | 停止・終了後の削除までの期間。例：`24h` |
| `Protect running main from idle` | 実行中のメイン処理をidle回収から保護。最大寿命は延長しない |
| `Supervise this VM while TUI is open` | 今回作成したVMだけを、このTUIで2秒ごとに監視・期限適用 |

- 一覧で`L`を押すと、更新時点の期限・残り時間・ホストが観測したrootfs使用量と容量／inode上限を表示します。`Refresh`で再取得します。取得できない場合は不明として表示します。共有フォルダーと独立コピーはホストの容量を使用し、このrootfs quotaの対象外です。
- `Supervise this VM…`は、既存の期限設定を持つ対象1台だけの監視を確認後に開始します。すでに期限切れなら直ちに停止・削除され得ます。`Stop TUI supervision`はこのTUIの監視だけを止めます。
- `Review due action…`で対象1台の期限切れ操作を確認し、承認すると現在の状態を再検査して適用します。確認した停止が保持期限による削除へ変わった場合は拒否し、再確認が必要です。停止はVMを保持し、保持期限による削除は管理worktreeも回収します。独立コピーは残ります。
- **期限を保存しただけでは自動回収は動きません。** このTUIの監視は終了時に停止します。終了後も適用する場合は、通常ユーザーの別ターミナル・監視サービスで次を継続実行します。こちらは明示的な期限設定を持つ全ワーカーが対象です。

    ```bash
    oaiso reap --watch
    ```

- 期限設定のない既存VMへ、この画面から新しい期限を書き込む機能ではありません。詳細は[寿命と再現性](../sandbox-features.md#寿命と再現性)を参照してください。

## ファイルを確認・転送する

実行中のVMを選び、`F`を押します。対象はゲストの`/workspace`内です。

| キー | 操作 |
|---|---|
| `Enter` | 実ディレクトリへ移動、またはテキストを表示 |
| `Backspace` | 親ディレクトリへ移動し、直前に開いていたフォルダーを選択 |
| `G` | 一覧を再取得。選択中の名前が残っていれば選択を保持 |
| `D` | 選択ファイルをホストの新しいファイルへダウンロード |
| `U` | ホストファイルを現在のworkspace配下へアップロード |
| `Esc` | 表示・入力を閉じるか一覧へ戻る |

- テキスト表示は先頭256 KiBまで。UTF-8以外やバイナリは表示せず、ダウンロードを案内します。制御文字は表示用に変換します。
- フォルダーの読み込みに失敗した場合は、移動前のパス・一覧・選択を保持します。エラーを閉じて再操作できます。初回取得の失敗は`G`で再試行してください。
- 転送は1ファイル64 MiBまで。双方とも既存ファイルを上書きせず、ディレクトリの自動作成は行いません。
- シンボリックリンクは開けません。転送先・元のホストパスも親ディレクトリを含めてシンボリックリンクを拒否します。
- アップロードは確認前に内容を固定し、サイズとSHA-256を表示します。`Esc`で取り消せます。
- ダウンロードは確認後に取得し、成功時だけ新しいファイルとして公開します。ホスト側は`0600`です。取得中にゲストが更新したファイルの一貫性までは保証しません。
- 共有workspaceへのアップロードはホストのプロジェクトにも反映されます。

## 差分を確認して成果物を回収する

利用可能：**未リリース（main）**。稼働中VMを選び、`W`を押します。

1. VM内のGit statusと**現在のHEADに対する未コミット差分**を確認します。表示は最大256KiBです。ゲストが作成したcommitの履歴比較や、未追跡ファイルの内容表示ではありません。ホストでゲストのGit設定を実行しません。
2. `Tab`で`Export selected files…`へ移動します。workspaceからの相対パスを1行1ファイルで指定し、新しいホスト側tarファイルを選びます。
3. `Review export`でファイル一覧・容量・guest HEAD・保存先を確認し、スクロールできる画面から承認します。
4. `Saved reviewed artifacts`が出たら保存完了です。VMとコピーは残ります。内容の確認・採用と、VMの削除は別の操作です。

- 既存ファイルへの上書き、symlink、秘密用のパス、256ファイル／32MiB超過を拒否します。選択内容・差分・HEADがレビュー後に変われば保存を拒否し、途中のファイルを公開しません。
- tarには選択したファイル、選択範囲の`changes.patch`、manifestを含めます。ホストファイルは0600です。元プロジェクトへ変更を自動適用しません。
- 管理workspaceでは[初回取り込みとのファイル比較とGit不要の回収](managed-workspaces.md#変更を回収する)を使います。通常の共有でGitがない場合や、大きな差分ではエラーを示します。個別ファイルは`F`から回収できます。[成果物の仕様](artifacts.md)も確認してください。

## Webアプリを確認する

組み込み`plain`イメージでworkspaceの内容を試す例です。**VM作成フォームの`Command`欄**に貼り付けます。ホストのターミナルで実行するコマンドではありません。

```bash
exec python3 -u -m http.server 3000 --bind 127.0.0.1 --directory /workspace
```

設定をレビューして作成すると、VM内のサーバーが起動します。自分のアプリを使う場合は、その起動コマンドとポートへ置き換えてください。

1. VM内でWebサーバーを起動し、ゲストのloopbackポートで待ち受けさせます。
2. 一覧で対象VMを選び、`U`を押します。
3. ポートと有効期間（5分・15分・30分・1時間）を選び、`Start`を選びます。
4. 表示された認証付きlocalhost URLを、このTUIを実行しているホストのブラウザで開きます。

- 既定ポートは3000、有効期間は30分。同時に最大4件、同じVM・ポートの重複は拒否します。
- URLは秘密として扱ってください。ブラウザへ自動では開きません。SSH先でTUIを使う場合、手元のlocalhostでは直接開けません。[プレビューの通信条件](preview.md)を参照してください。
- `Tab`で入力欄・ボタン・URL一覧を順に移動できます。`Shift-Tab`は逆方向、`Ctrl-L`はURL一覧への直接移動です。どの領域でも`Esc`で一覧へ戻ります。
- URL一覧へ移動し、対象で`Enter`を押すと停止確認を表示します。`Stop all for this worker`も使用できます。
- 一覧へ戻ってもプレビューは有効です。停止操作、有効期限、VM停止、TUI終了で既存接続も閉じます。
- プレビューの停止だけではVM内のサーバーは終了しません。不要なVMは一覧の`S`／`D`で停止・削除します。
- `Q`でTUIを終了してもVMは残ります。不要になったVMは一覧から停止・削除してください。

起動失敗は`oaiso runtime-check`と表示されたエラー、ファイル取得失敗はVMの稼働状態・アクセス権・サイズ、プレビュー失敗はゲストの待受ポートを確認してください。

## CLIで単発の動作確認をする

未リリース（main）：TUIを開かずにコマンドを実行する場合も、同じ準備済みホスト・イメージを使います。通常ユーザーで作業プロジェクトから実行します。この例はworkspaceを読み取り専用にします。

```bash
oaiso run --runtime kata --agent shell --no-ai --no-internet \
  --image codex-dock:latest --read-only \
  -- python3 -I -c 'import os; print("sandbox-ok", os.getuid())'
```

出力の抜粋例。UIDは環境により異なります。

```text
sandbox-ok 1000
```

終了コード0なら、そのコマンドがVM内で成功しています。既定では終了したワーカーを削除します。AI認証・推論の確認は行いません。フラグの詳細は[`run`](../commands/run.md#ai認証なしのサンドボックス)を参照してください。

## 終了・停止・削除を区別する

| 操作 | VM・保存内容への影響 |
|---|---|
| 接続したシェルで`exit` | TUIへ戻る。VMは動作を継続 |
| 一覧で`Q` | TUIが管理するプレビューを閉じる。作成したVMは保持 |
| 一覧で対象を選んで`S` | VMを停止し、再起動用に保持 |
| 停止した対象で`R` | 保存した起動コマンドを再実行。メモリの途中状態は再開しない |
| 対象で`D` | 確認後にVMと管理資源を削除。必要なファイルは先に回収 |

通常の共有プロジェクトはホストに残ります。ただし、管理されたGit worktreeは削除対象です。[共有ファイルと所有者](../workspace.md)を確認し、必要な成果をダウンロードしてから削除してください。
