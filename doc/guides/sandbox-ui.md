# TUIでサンドボックスを使う

**日本語** | [English](../en/guides/sandbox-ui.md)

利用可能：**未リリース（main）**。AI認証を使わず、Kata VMの作成、workspace内のファイル確認・転送、Webアプリの確認ができます。

## 前提と起動

- Linux/KVMの[ノード導入](../setup.md)を管理者が完了し、利用者がノードソケットへ接続できること。
- 書き込み可能rootfsには、ノードで設定した[quota対応の専用ストレージ](storage-migration.md)が必要です。
- 作業するホストのプロジェクトディレクトリで、通常ユーザーとして起動します。

```bash
oaiso ui
```

## VMを作成する

1. 一覧画面の`Actions F2`から`New sandbox`を選ぶか、`N`を押します。
2. ホストのプロジェクト、イメージ、必要なら起動コマンドを指定します。空欄ならVMを待機状態に保ち、作成後に`C`でシェルへ接続します。
3. CPU・メモリ、共有フォルダ、通信設定を確認し、`Review`を選びます。
4. 確認画面で作成を承認します。`Created sandbox`が出たら一覧へ戻り、対象を選んで`C`で接続、`Enter`でログを確認します。

| 項目 | 既定値・意味 |
|---|---|
| Runtime | Kata。通常の起動検証を通ります |
| Name | 空欄なら自動生成 |
| Image | 空欄ならホスト・プロジェクト設定の解決規則を使用 |
| Command | 空欄なら`exec sleep infinity`で待機。指定内容はホストのプロセス引数に含めずstdinで渡す |
| CPU / memory | ノードが承認したプロファイルから選択。既定なら既存設定を継承 |
| Project access / Image rootfs | 既存設定の継承、読み取り専用、書き込み可能から選択 |
| Storage | ノードのrootfs byte・inode上限を表示。共有ホストフォルダの容量は対象外 |
| Internet access | 既定はOffline。Host policy、依存レジストリ、指定ドメインも選択可。ホストの禁止規則は維持 |
| Enable AI services (optional) | 既定は無効。無効時は認証Proxy・資格情報を使わない。一般通信の許可には資格情報を持たないProxyを使う |
| Extra mounts | 1行に1つ、通常の`--mount`形式。共有範囲を確認して指定 |

- 起動は通常の`oaiso run`を使用します。未指定項目にはホスト・プロジェクトの既定値が適用されます。ホスト設定は変更しません。
- `Esc`は確認・入力を取り消します。起動中は完了を待ちます。失敗表示に名前が出た場合は、再試行前に一覧で残存を確認してください。
- プロジェクトが書き込み可能なら、ゲストの変更は共有ホストフォルダへ反映されます。隔離が必要な作業ではコピーしたプロジェクトや読み取り専用共有を使ってください。
- AI routesを有効にする場合は、[認証設定](authentication.md)を先に行ってください。

## ファイルを確認・転送する

実行中のVMを選び、`F`を押します。対象はゲストの`/workspace`内です。

| キー | 操作 |
|---|---|
| `Enter` | 実ディレクトリへ移動、またはテキストを表示 |
| `Backspace` | 親ディレクトリへ移動 |
| `G` | 一覧を再取得 |
| `D` | 選択ファイルをホストの新しいファイルへダウンロード |
| `U` | ホストファイルを現在のworkspace配下へアップロード |
| `Esc` | 表示・入力を閉じるか一覧へ戻る |

- テキスト表示は先頭256 KiBまで。UTF-8以外やバイナリは表示せず、ダウンロードを案内します。制御文字は表示用に変換します。
- 転送は1ファイル64 MiBまで。双方とも既存ファイルを上書きせず、ディレクトリの自動作成は行いません。
- シンボリックリンクは開けません。転送先・元のホストパスも親ディレクトリを含めてシンボリックリンクを拒否します。
- アップロードは確認前に内容を固定し、サイズとSHA-256を表示します。`Esc`で取り消せます。
- ダウンロードは確認後に取得し、成功時だけ新しいファイルとして公開します。ホスト側は`0600`です。取得中にゲストが更新したファイルの一貫性までは保証しません。
- 共有workspaceへのアップロードはホストのプロジェクトにも反映されます。

## Webアプリを確認する

1. VM内でWebサーバーを起動し、ゲストのloopbackポートで待ち受けさせます。
2. 一覧で対象VMを選び、`U`を押します。
3. ポートと有効期間（5分・15分・30分・1時間）を選び、`Start`を選びます。
4. 表示された認証付きlocalhost URLを、このTUIを実行しているホストのブラウザで開きます。

- 既定ポートは3000、有効期間は30分。同時に最大4件、同じVM・ポートの重複は拒否します。
- URLは秘密として扱ってください。ブラウザへ自動では開きません。SSH先でTUIを使う場合、手元のlocalhostでは直接開けません。[プレビューの通信条件](preview.md)を参照してください。
- `Tab`で入力欄・ボタン・URL一覧を順に移動できます。`Shift-Tab`は逆方向、`Ctrl-L`はURL一覧への直接移動です。どの領域でも`Esc`で一覧へ戻ります。
- URL一覧へ移動し、対象で`Enter`を押すと停止確認を表示します。`Stop all for this worker`も使用できます。
- 一覧へ戻ってもプレビューは有効です。停止操作、有効期限、VM停止、TUI終了で既存接続も閉じます。
- `Q`でTUIを終了してもVMは残ります。不要になったVMは一覧から停止・削除してください。

起動失敗は`oaiso runtime-check`と表示されたエラー、ファイル取得失敗はVMの稼働状態・アクセス権・サイズ、プレビュー失敗はゲストの待受ポートを確認してください。
