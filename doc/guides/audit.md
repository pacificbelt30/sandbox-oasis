# 操作の監査記録を保存する

**日本語** | [English](../en/guides/audit.md)

- 利用可能：v0.0.4。
- 用途：誰の値を使ったかではなく、操作対象のID・理由・操作・成否を後から確認する。

## 保存する操作と場所

| 対象 | 操作 | 保存場所 |
|---|---|---|
| node | VMの作成・開始・停止・削除、checkpoint作成・削除 | nodeのstateディレクトリ内の`audit/` |
| 管理されたAuth Proxy | token発行・権限付き発行・復元・失効、通信拒否 | `usage-state-dir/audit/` |
| 独立した認証ストア | 作成・OAuth更新・暗号化移行・鍵方式変更 | profileルートの`audit/` |
| 組み込みAuth Proxy | 上記Proxy操作 | `Config.AuditDirectory`を指定。省略時は`UsageStateDir/audit/`。両方空なら保存しない |

- `proxy serve --audit-dir /絶対パス`で保存先を指定できます。
- Go APIのケースProxyは`CaseProxyOptions.UsageStateDir`を指定すると、その下の`audit/`へ保存します。独自Storeを使ったOAuth更新もProxy側で記録します。
- 作業VMへ監査領域を共有しないでください。
- 上流資格情報、placeholder、鍵、本文、URL、任意のエラー本文は保存しません。
- 対象IDはSHA-256で記録します。推測しやすいIDの匿名性を保証するものではありません。
- 理由は`completed`・`failed`・`canceled`・`storage_full`・通信拒否コードなどの固定値です。任意のエラー本文は残しません。
- 各操作に`intent`と結果`ok`／`error`を記録します。結果のない操作は未確定です。`error`は失敗応答の記録で、変更がなかったことの保証ではありません。
- 同一VM内の任意コマンドや上流の処理内容をすべて記録する機能ではありません。

## 検証・出力する

保存先の所有ユーザーで実行します。nodeの監査領域は管理者が読み取ります。`/絶対パス/audit`を対象の実パスに置き換えてください。

```bash
oaiso audit --directory /絶対パス/audit > audit.json
```

- 終了コード0：連番・ハッシュ連鎖・保存済み末尾が一致し、未確定操作なし。
- `pending`あり：JSONを出力してエラー終了。対象のVM・Proxy・認証状態を照会して判断します。
- 欠損・書込み途中・保存済み末尾との不一致：エラー終了。自動修復や成功扱いはしません。

## 容量・障害・保護範囲

| 条件 | 動作 |
|---|---|
| 保存権限 | 所有ユーザー専用ディレクトリ0700、通常ファイル0600。symlink・hard linkを拒否 |
| 容量 | 1領域あたり16 MiB。自動削除なし。GoのJournal指定は1 KiB–64 MiB |
| 容量不足・disk full・監査破損 | 新規VM作成・開始、token発行・復元、認証変更を拒否 |
| 停止・失効・削除 | 監査保存の失敗だけを理由に妨げない。サービスのログに保存失敗を記録 |
| 操作後の結果保存失敗 | 操作が済んでいる可能性がある。nodeは503、認証変更はエラー。状態確認前の再送を避ける |
| Proxy発行後の結果保存失敗 | 発行tokenを取り消してエラー。権限を残さない |
| 中途終了 | intentが残り、結果がなければ未確定。末尾不一致なら追加の権限付与を拒否 |
| 改ざん | 連番・ハッシュ連鎖・別の末尾ファイルで欠損を検知。同一UID・rootが一式を書き換える攻撃は防がない |

- 容量到達前に対象サービスを停止し、`audit/`全体を外部の管理先へ退避します。退避物を検証・保管後、新しい空の0700領域で再開します。
- 退避前後は別の記録区間です。退避物の連続性・保存先・保管期限は運用側で管理します。
- 意図的な消去や、古い監査一式への巻戻しをローカルの情報だけで完全に検知することはできません。
